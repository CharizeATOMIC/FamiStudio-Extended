FamiStudio Tuning — Revision 9 / 修订版 9
Based on FamiStudio 4.5.3 / 基于 FamiStudio 4.5.3
Project format / 工程格式: 1007

中文
====

这是独立开发分支，不是 FamiStudio 官方发行版。保留上游版权和许可证。
GitHub 仓库、分支及给原作者的提案目前仍处于准备阶段，尚未发布或发送。

本次改进
--------
1. 普通乐器恢复四个原生包络图标，不再给每个音色增加三枚噪波图标。使用
   硬件噪波的乐器只显示一个“噪波设置”入口，菜单以文字区分硬件音量和
   包络重启，不再用相同喇叭图标表示不同操作。
2. 较少使用的硬件参数默认收起为同页一行，并提示已启用项数。收起不改
   声音。关闭扫频时不再显示三个灰色从属参数。“另存为”保留可见文字
   入口，去掉第二个磁盘图标；Ctrl+Shift+S 和保存右键菜单继续可用。
3. 新噪波音高统一用琴键和原生乐器琶音编辑，不再提供独立噪波周期编辑器
   或跟随开关。硬件音量和重启仍可编辑，并说明它们何时覆盖软件音量。
4. 旧工程不会被自动改声或静默迁移。旧周期数据继续兼容读取、播放和导出，
   编辑器显示来源提示。通过“将旧噪波音高转为琶音”明确发起迁移，成功后
   用普通琶音编辑，可撤销恢复。共享于其他通道、已有非零乐器琶音、独立
   琶音、固定周期含非 C4 音符/滑音、无攻击衔接或无法表示的数据都会说明
   原因并保留原样，不强行套用转换。
5. 七语言补齐上述界面及迁移提示，并修复旧噪波帮助文字被 INI 英文分号
   截断的问题。R9 仍使用格式 1007，不改声音引擎格式、原生 DSP 或 ABI。

R8 的原子保存修复继续保留：完整写入并刷新临时文件后再替换目标，取消/
失败不改当前路径、脏状态或原文件，也不会继续关闭/切换工程。另存为成功
后，普通保存写入新路径。长文件名、只读目标及平台权限边界见移植说明。

本分支累计新增功能
------------------
• 每首歌、时间轴每列样式可覆盖 A4 标准音及十二个音级的音分偏移；关闭覆盖
  即继承上一级。A4 为 300–580 Hz，各音级偏移为 ±1200 音分。
• 工程全局的八类芯片、每类 96 个音可直接设置整数硬件周期/频率值。完整
  横向键盘支持缩放、滚动、拖动和输入。显示轴为默认值 ±50，输入可超过
  显示范围，受所选硬件表示的实际边界限制。播放和出口共用频率量化。
• 扩展芯片勾选项右侧直接调整数量，最多每类八份、总计 64 声部。每首歌
  可实时设置各声部立体声及声像，适用于监听、预览和音频导出。
• NSF/NSFe 导入可多选子曲并分别设置捕获时长，批量合并到一个工程，支持
  取消和资源去重。这仍是寄存器捕获导入，不是通用原游戏乐器反编译器。
• 原生噪波琶音、硬件音量/重启宏，软件包络衰减效果，样式播放延迟和循环
  变奏，使完整的乐器程序及首次/重复演奏区别可编辑、可导出。旧周期宏
  作为兼容数据保留，安全时可显式迁移为原生琶音。
• 可选 APU 方波起音相位重置、方波/三角波音高宏低字节饱和，以及真实
  方波硬件扫频。DPCM 每键映射可保存完整 0–127 初始 DAC，包括奇数。
• 项目输出更新率可选 1×/2×/4×，同制式约为 NTSC 60/120/240 Hz、
  PAL 50/100/200 Hz。已有歌曲和宏保留自己的时基，因此切换输出率不改变
  原速度，也不会自动把旧歌曲网格扩成四倍。新歌曲/宏使用创建时的项目率。
  包络属性可保时长转换步进率；不能精确表达或超出长度限制的转换会明确
  拒绝，不静默丢步骤。输出率也不能低于实际使用的歌曲/包络时基。
• 全部七种既有语言覆盖新增界面；数值加减区域增大，支持直接输入。修复
  S5B 重置确定性、NSF 自定义周期及 APU 扫频模拟中的实际问题。工程采用
  无损 Brotli 压缩，撤销及剪贴板保持各自原有压缩协议。

兼容与使用边界
--------------
• 可读取上游格式至 19 以及本分支 1001–1007。R9 与 R8 同为格式 1007，
  R8 可以读取这种格式，但没有 R9 的编辑流程；官方版及 R1–R7 无法读取。
  旧 1006 的 Brotli 和 Deflate 均可读取。请用另存为保留原工程。独立设置
  目录为 FamiStudio-Tuning。
• 自定义调音、芯片曲线和新增演奏语义用于 FamiStudio 声音引擎/NSF/NSFe
  时，需要匹配本分支引擎及出口头部列出的编译选项。独立引擎的新增选项
  默认关闭；未开启功能的旧游戏无需承担这些可选状态和处理分支。
• 重复的同型号芯片只用于编辑和音频路径，NSF/NES/FDS/声音引擎及 VGM
  不接受重复芯片。立体声和声像只属于音频混音，不写入这些硬件格式。
• 高倍率目前支持同 NTSC/PAL 制式播放、音频及 FamiStudio 引擎/NSF/NSFe。
  普通 NES/FDS 导出模板、高倍率跨制式转换及不能保真的旧格式出口会明确
  拒绝。另有原创定时器卡带示例展示游戏如何均匀调用高倍率引擎；游戏需
  自行安排 IRQ/计时器并评估 CPU 预算，视频帧回调不能替代均匀子帧调度。
• FamiTracker 速度模式在编辑器中保留支持；这与“导出为 FamiTracker 文件”
  是两回事。声音引擎导出中的样式延迟目前要求 FamiStudio 速度模式。
  无法表达调音/新演奏语义的 FamiTracker、FamiTone2、MIDI 等出口会报错。
  VGM 不支持本分支样式延迟/循环变奏/高倍率输出。
• 噪声、DPCM、节奏声部继续受真实硬件行为限制。FM 比率及调制仍参与音色。
  立体声分轨混音不保证等于原本单声道的非线性混音。

English
========

This is an independent development fork, not an official FamiStudio release.
Upstream copyright and license notices are retained. Repository publication and
the upstream proposal remain preparation work; neither has been posted or sent.

Revision 9 changes
------------------
• Regular instruments regain their four native envelope icons. Hardware-noise
  instruments have one Noise settings entry with named hardware-volume and
  restart actions, instead of repeated speaker icons across the main row.
• Less-used hardware options start folded into one inline row with an enabled
  count. Folding never changes sound. Disabled sweep hides its three subordinate
  controls. Save As stays visibly labeled but loses the second disk icon. Its
  shortcut and the Save context menu remain available.
• New noise pitch uses keys and the native instrument arpeggio. The separate
  noise-period editor and follow-note switch are removed from the UI. Hardware
  volume/restart controls and their software-volume override help remain.
• Old projects are never silently migrated or retuned. Legacy period data remains
  readable, playable and exportable, with a visible compatibility hint. An explicit
  Convert legacy noise pitch to arpeggio action checks whether the conversion is
  lossless. Shared channels, existing nonzero arpeggios, independent arpeggios,
  incompatible fixed-period notes/slides, no-attack continuity and unsupported
  data report a reason and remain intact. Successful migration is undoable.
• Seven-language help and migration messages are included. Existing noise hints
  no longer truncate at an INI semicolon. Format remains 1007, with no revision 9
  engine-stream, native DSP or ABI change.

Revision 8's atomic save protection remains: cancelled/failed writes preserve
the path, dirty state and original file and block pending close/open operations.
Successful Save As becomes the target of subsequent saves. Platform metadata and
link validation boundaries remain documented in PLATFORM_HANDOFF.txt.

Cumulative fork features
------------------------
• Song and pattern-column overrides of A4 reference and twelve cents offsets;
  disabled overrides inherit. A4: 300–580 Hz; pitch-class offsets: +/-1200 cents.
• Project-global 96-note integer hardware curves for eight chip types, with a
  full horizontal keyboard, zoom, scrolling, drag and direct input. The visible
  +/-50 band is relative to each default; manual values may exceed it within the
  selected hardware representation. Playback/export share pitch quantization.
• Expansion-copy counts beside their checkboxes (up to eight per type, 64 total
  channels), and per-song channel stereo/pan for preview, playback and audio.
• Multi-subsong NSF/NSFe capture into one project, individual durations, safe
  resource merging and cancellation. This is not a general source-engine decoder.
• Native noise arpeggios, hardware volume/restart macros, compatible legacy period
  data, software envelope decay, delayed patterns and loop
  variants; optional APU attack phase reset, pitch-envelope low-byte saturation
  and hardware pulse sweep; full 0–127 initial DAC in each DPCM key mapping.
• Independent 1x/2x/4x output, song and envelope clocks. Changing output rate keeps
  existing music speed and authored grid resolution. New resources use the
  current output clock. Envelope-rate conversion preserves duration where exactly
  representable, otherwise reports the incompatible resource before mutation.
• Seven-language controls, larger numeric hit areas, direct input, deterministic
  S5B reset, NSF timing/sweep corrections and lossless Brotli project storage.

Compatibility
-------------
R9 retains R8's format 1007 and reads official formats through 19 plus fork
1001–1007, including both 1006 compression variants. R8 shares the file format,
but not the new editor workflow. The official application and fork revisions
through 7 cannot read 1007. Use Save As to retain originals. Settings use the
separate FamiStudio-Tuning path.

Hardware exports require matching engine sources and the options emitted in the
export header. New standalone engine options default off. Additional chip copies
are audio-only and rejected by NSF/NES/FDS/engine/VGM exports; stereo/pan is not
encoded into hardware data. Noise, samples and rhythm retain hardware limits.

High-rate playback/audio/engine/NSF/NSFe currently require the same video region.
High-rate cross-region operation, ordinary NES/FDS templates and unsupported
legacy formats are rejected. A separate original mapper-timer cartridge shows
uniform game scheduling; integrators must provide the timer/IRQ and CPU budget.
Editor FamiTracker tempo remains supported; FamiTracker file export is a separate
compatibility question. Engine pattern delay currently requires FamiStudio tempo.
VGM rejects delay, loop variants and high rate. Other legacy exporters reject
features they cannot preserve instead of silently dropping them.

Verification and distribution
-----------------------------
R9 passes 4,732 backend checks: eight repeated suites total 2,896 (default 1,506,
articulation playback 124, envelope clocks 134, instrument articulation 76, noise
envelopes 141, noise following 597, saving 22 and update rates 296). The 1,836 new
migration checks cover 36 scenarios and 72 actual NSF executions at PAL/NTSC and
1x/2x/4x. All seven UI languages at 100% and Chinese at 150% pass: eight runs and
1,869 PASS records, including narrow-label geometry and legacy-conversion access.
The final GUI runs use an isolated portable directory. Non-portable test execution
is refused before application initialization to protect everyday settings.
A private four-song migration comparison matches 53,314,344 editor PCM samples
across the full mix and isolated noise. Actual NSF CPU execution matches 258,397
ordered APU/S5B address/value writes over 36,328 music ticks. CPU write timestamps
and NSF PCM are not claimed identical. The final self-contained EXE also matches
the preceding release for four 12-second excerpts of 529,200 samples each, while
an original clock example matches all 176,400 samples at each of 1x/2x/4x.
R9 Windows self-contained publication and Linux/macOS managed builds succeed with
zero errors. All eight native DLLs match the source directory and R8 by SHA256.
The engine and native DSP are unchanged, so R8 engine evidence is retained rather
than counted as rerun R9 tests: 64 four-assembler configurations, 31,956 layout
checks over 60 NES/FDS templates, and eight CPU loops plus 660 independent FCEUmm
video frames per original timer-cartridge rate.
The Windows account cannot create symbolic links, so that test is explicitly
skipped. Unix permissions/links, target-OS audio and packaging still need runtime
validation. Rebuild the native ABI on each target OS. Android
still needs the matching .NET 9 Android toolchain and device testing. No physical
NES/FC console has been tested. Extracted commercial-game assets and derived
projects remain private and are excluded from public application/source packages.
Already tracked upstream examples and their notices remain unchanged.
