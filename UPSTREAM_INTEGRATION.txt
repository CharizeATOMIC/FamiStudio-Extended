Priorities and dependency order / 优先功能与依赖顺序
-------------------------------------------------
The user-facing priorities are song/pattern tuning, absolute chip curves,
multi-subsong NSF import, live pan/optional chip copies and speed-preserving
1x/2x/4x clocks. Noise articulation and UI cleanup are separable follow-ups.
Review priority is not a requirement to apply historical commits in that order.
C# source paths below are relative to FamiStudio/ unless otherwise stated.

1. Multi-subsong NSF import: a small independent editor/I/O PR.
   Main files: Source/IO/NsfFile.cs, App/Common/Dialogs/NsfImportDialog.cs,
   existing project resource-merge APIs, and the dialog's seven locale sections.
   Test: Tests/TuningRegression/NsfMultiImportRegression.cs.
   Preserve selected order, per-track duration, resource ownership/deduplication,
   cancellation, failure and prior single-track CLI semantics. Reuse the target
   branch's merge implementation rather than replacing its whole Project.cs.
   No music opcode or native audio ABI is required just for multi-selection.

2. Song/pattern tuning: model -> quantizer/playback -> export -> UI as one feature.
   Source/Project/TuningSettings.cs, Project.cs, Song.cs, Pattern.cs;
   Source/Player/CustomTuningTables.cs, NesApu.cs, InstrumentPlayer.cs;
   Source/ChannelStates/ChannelState.cs; IO/FamistudioTextFile.cs and
   FamitoneMusicFile.cs; App/Common/Dialogs/TuningProperties.cs.
   Full inheritance includes A4 and all twelve cents offsets. Preserve tuning
   for held notes, slides, loop entry and keyboard preview, not only new attacks.
   Include binary/text/undo/clipboard and selected-song legacy-export guards.
   Coordinate the optional custom-tuning engine and embedded kernels below.

3. Absolute chip curves: build on the shared quantization/export contract in #2.
   Source/Project/ChipTuningSettings.cs, Player/CustomTuningTables.cs;
   App/Common/Dialogs/ChipTuningDialog.cs, Controls/ChipTuningCurve.cs and
   ProjectPropertiesDialog.cs. Test: ChipCurveRegression.cs / CurveUiTests.cs.
   Retain sparse defaults, basis metadata and chip-specific representation
   limits. In particular, VRC7 uses each note's canonical fixed block; it is not
   an unrestricted raw f-number UI. Graph +/-50 is a display/drag band, not the
   storage limit. The existing $5f table instruction serves these curves too.

4. Live channel stereo/pan first; repeated expansion copies as a separate PR.
   Source/Project/Song.cs, Project.cs, Channel.cs; Player/BasePlayer.cs,
   InstrumentPlayer.cs, WavPlayer.cs and NesApu.cs; song/project properties;
   ThirdParty/NesSndEmu/DllWrapper.cpp, Mixer_Apu.h and SndEmu.def.
   Port context creation/destruction and channel/copy identity through mute,
   preview, N163 allocation, clipboard, import and audio stems together.
   Native nonlinear mixing and stem balance are not interchangeable. Extra
   copies are editor/audio features: hardware exporters must reject them.
   This unit requires matching native libraries on each platform, but not a
   new music-engine opcode. Authors can accept pan and decline chip copies.

5. Independent update clocks: a separate full-stack feature after baseline audio.
   Project.UpdateRateMultiplier, Song.LogicRateMultiplier and
   Envelope.TickRateMultiplier; BasePlayer/InstrumentPlayer, ChannelState,
   WAV/video timing; native Simple_Apu.cpp/.h and DllWrapper.cpp;
   NotSoFatso NSF_File/NSF_Core rate handling; NsfFile and music/SFX export.
   Preserve existing authored song/macro clocks when output changes. New
   resources use the current output clock. Envelope-rate conversion must preserve
   duration/loop/release and reject unrepresentable data before mutation.
   Render substeps at uniform native cycle intervals. Updating only the header,
   BPM or number of calls at one frame boundary is not equivalent.
   Include NSF/NSFe period execution, output duration, preview and multi-chip
   stems. High-rate cross-region cases and ordinary NES/FDS templates currently
   refuse unsupported scheduling. Games must supply uniform timer/IRQ calls.

6. Optional follow-ups: save atomicity/discoverability, readable hardware-noise
   envelopes and explicit legacy migration, software decay, pulse articulation/
   sweep, DPCM seven-bit mapping DAC, pattern delay/loop variants, compression.
   Each can be reviewed separately, but retain its model/player/export contract.
   R10 specifically places hardware volume/restart buttons directly in the
   folded hardware group, with step/unused labels and no intermediate menu or
   extra instrument-row noise icon. This requires no native or engine change.

以上按依赖拆功能，不要求作者接收整个分支。多曲导入可先单独合入；调音与
芯片曲线共用量化及引擎表协议；实时声像可与重复芯片拆开；高更新率必须连同
歌曲/包络时基、原生子帧、NSF 调度完整审查。噪波、界面、保存和其他演奏语义
可随后逐项讨论。各平台共享 C# 并不等于无需重编和验证原生层。

Engine and native integration boundary / 引擎与原生边界
------------------------------------------------------
Optional standalone switches all default to 0:
  FAMISTUDIO_USE_CUSTOM_TUNING        $5f  tuning-table pointers
  FAMISTUDIO_USE_NOISE_ENVELOPES      $60  period/control/restart macro pointers
  FAMISTUDIO_USE_ENVELOPE_DECAY       $61  software volume decay interval
  FAMISTUDIO_USE_APU_INSTRUMENT_FLAGS $62  attack phase / timer-byte clamp flags
  FAMISTUDIO_USE_PULSE_SWEEP          $63  pulse sweep register
  FAMISTUDIO_USE_UPDATE_RATE          $64  output rate and song divider
These are this fork's assignments, not reserved upstream opcode allocations.
For an accepted feature, update the C# emitter and all relevant CA65, ASM6,
NESASM, SDAS sources plus CA65 multi-expansion source as a unit. Regenerate the
embedded NSF/NES/FDS variants with Tools/build_tuning_nsf.py and
Tools/build_tuning_rom.py, keeping exporter bank/data boundaries consistent.
Do not copy only an opcode handler or only an exported song into an old kernel.

Clocked envelopes retain their bytecode: an optional divider precedes the macro
label. $64 enables clock state. Songs/effects and envelopes have independent
dividers; restart pulses must not repeat while waiting. SFX keep their original
base rate. Default-off configurations avoid the new optional state/update work.
Enabled high rates increase total CPU work and require per-game timing budgets.

Native ABI additions for contexts/mixing and NesApuSetUpdateRateMultiplier require
new native builds per OS. NotSoFatso period/sweep fixes must be reviewed with its
CPU/APU scheduling; a C#-only port leaves that behavior incomplete. R9/R10 change
none of this ABI or DSP, but adoption of the cumulative fork does. Keep native
fixes and optional features separate where their dependencies allow it.

文件格式与兼容 / File format and compatibility
---------------------------------------------
Private format is 1007; R8/R9/R10 share it. Reads include official formats through
19 and fork 1001..1007. Versioned additions are tuning/copies (1001), chip curves
(1002), noise/sequence semantics (1003), articulation (1004), full mapping DAC
(1005), sweep/clocks and compression transition (1006), legacy noise following
(1007). Preserve both accepted 1006 compression markers. Upstream should choose
its own schema/versioning; do not assign 1007 to a new upstream format blindly.

Changing persistence requires binary/text/undo/clipboard/hash/equality and old
default tests together. R10 hides the independent period editor but retains its
legacy serialized fields and runtime/export behavior. Migration is explicit,
undoable and refused when not provably lossless. Dropping hidden fields on load
would silently change existing projects. Unsupported exporters must fail clearly.

Acceptance checklist / 合入验收
-------------------------------
Record the actual upstream target SHA, compare its current equivalents, and
port one unit onto a clean branch. Use upstream's own serialization/opcode/API
choices. Keep synthetic fixtures public; newly extracted commercial-game ROM,
sample, instrument, score and derived projects remain outside public patches.
For each unit, verify default behavior, persistence, undo/clipboard, cancellation
where relevant, all seven UI languages, and real exported CPU behavior when the
unit affects playback. Recheck assembler parity and ROM/RAM layout when engine
code changes. Use Tests/RunUiSmoke.ps1 for isolated portable GUI execution.

R10 direct-control UI passes eight isolated runs: seven languages at 100% and
Chinese at 150%, with 1,981 PASS records and unchanged user INI hashes. This
evidence predates the separate branding build. Branded Windows publication and
Linux/macOS managed builds pass with zero errors. FamiSpectrum.exe passes -help
and an exact four-second PCM comparison with FamiStudio.exe. Final release PCM
matches R9 across four 12-second excerpts and the original 1x/2x/4x clock example.
All eight native DLLs match R9 and the source directory. These builds test the
local fork, not the separately produced merged tree. Target-OS native execution,
device audio, signing/notarization, Android and physical NES/FC remain separate
work. Source and CI are provided, but no remote CI run is claimed.
