Maintenance assessment

The three desktop versions share the tuning model, serialization, export code,
property controls, translations and native C++ mixer. Routine feature fixes can
therefore be made once and built for each desktop OS. Initial upstream adoption
still needs a design review; this fork changes the project format, music stream,
bundled drivers and native ABI. It is not a drop-in UI patch.

Suggested review order:
1. Song/pattern tuning, twelve-note temperament and project chip curves, with the
   optional engine table instruction and shared playback/export quantizer.
2. Multiple NSF subsong selection and safe merging, an independent importer change.
3. Channel stereo/pan and its native mixer.
4. Repeated expansion chips, if they fit the maintainers' desired product scope.

Before upstream merge, maintainers should choose the official format version and
opcode, review ROM/RAM/CPU budgets, and decide which optional features to accept.
Format 1007 and the separate settings directory intentionally identify this fork;
they should not silently become the upstream format/settings policy.

Revision 3 architecture and format

Project.ChipTuning stores one 96-note curve for each of the eight chip types.
ChipTuningSettings stores absolute integer hardware values. Graph dragging uses
the FamiStudio default +/-50, clipped by hardware limits; manual entry can exceed
this band within the selected hardware representation's limits. A sentinel marks
unedited points.
The curve retains its reference Hz, PAL/NTSC clock and N163 channel count; a fresh
curve can adopt the project's basis, while active curves retain their saved basis.
Playback derives pitch from the hardware value, scales by the effective reference
Hz divided by the saved reference Hz, applies the twelve-note cents temperament,
then quantizes for the playing region/chip. The curve itself is not cents-based.
It is project-global; copies of a chip share the same curve and octave-specific
points remain independent. Noise, DPCM and rhythm voices keep existing behavior.
Default/reset curves retain the original audio path and unaffected table entries.

Canonical units: APU/MMC5/VRC6 pulse timer, S5B actual tone period, FDS 12-bit
frequency word, N163 full 18-bit frequency word, VRC7 F-number at the displayed
default block, EPSM PSG period. VRC6 saw and EPSM FM derive their nearest registers
from the same resulting pitch. VRC7 bounds keep the F-number in the displayed
default block: 1..511 for block 0, 256..511 for higher blocks. This is a canonical
table-representation constraint, narrower than the physical chip's full range.
N163 words include the extra two frequency bits. The APU triangle retains
the existing octave relationship to pulse.

The editor shows the complete 96-key horizontal keyboard, with zoom and scrolling
for detailed editing. Shared PianoRoll helpers draw the native key gradients,
highlight colors and rotated key geometry. Names follow the existing editor's
C0..B7 convention rather than changing channel-specific acoustic octave rules.
Small arpeggio-like blocks use a -50/0/+50 axis relative to each note's default,
making the unchanged curve flat; labels show absolute integer hardware values.
Manual values outside this band keep their exact value and label, with only the
drawn block clipped at the edge. The model, serialization
and export do not restrict them to the drag band. The existing project-info page
opens the editor. Accepting the child does not mutate the project until the parent
dialog is accepted; project undo and
player recreation are part of the same transaction. Song/pattern tabs are unchanged.

Format 1002 reads official project formats through 19 and fork format 1001.
Earlier readers cannot read 1002. Global curve conflicts reject a song merge before
mutating its destination, because a per-note chip curve cannot be represented by
a twelve-pitch-class song override. Empty destinations adopt the incoming curves;
instrument-only imports remain allowed. Sparse text entries are, for example:
  ChipTuningBasis ReferenceHz="440" PAL="False" N163Channels="1"
  ChipTuning Chip="S5B" Note="46" Value="255"
The base chip uses Chip="APU". Note IDs are 1..96. Values and the saved basis are
preserved exactly in binary/text/undo; there is no conversion to floating offsets.

The NSF/NSFe dialog selects several subsongs from one file, retaining individual
capture durations and a cancellable batch. NsfFile.LoadSongs assembles a temporary
project and returns no partial result on failure/cancellation. Imported song and
resource names cannot silently alias; identical resources are shared only after
the importer checks their data and sample mappings. This is the existing register
capture approach, not a general source-instrument or game-engine decoder.

All seven languages cover the new curve, import and validation controls/messages.

Revision 4 integration addendum

The shared model now includes optional hardware noise macros, software volume
envelope decay, per-pattern video-frame playback delay, and a same-channel
loop-variant reference. Version 1003 reads fork versions 1001/1002 as well as
official projects through 19. All seven language files include the new controls.
The existing piano roll edits first-pass or loop-variant notes. Resource cleanup,
clipboard remapping, independent pattern copies and tempo resizing include both.

FamitonePlaybackCompiler.cs is included in all four managed platform projects.
It compiles note events and their owner-aware stop/release events without changing
the source project. FamiTracker-tempo playback delay is explicitly unsupported by
sound-engine export; FamiTracker-tempo loop variants without delay are supported.
The hardware engine has optional $60 noise-macro and $61 envelope-decay opcodes.
Standalone flags default off; bundled drivers are rebuilt with both enabled.
Regular NES TOC is $F900, EPSM TOC $FBA0; FDS TOC $7700 and music $7900.
These addresses must be changed together in linker configs and the image exporter.
The FDS song area is now $4700 bytes. Check ROM/RAM/CPU budgets before adoption.

The musical loop markers in a project are preserved. An exported stream may need
an initial pass followed by a repeat stream when inherited articulation differs;
the exporter deduplicates shared byte sequences. Do not rotate the editor's loop
or lengthen its introduction merely to obtain repeatable register state.

Revision 4 desktop managed builds are tested on Windows only; Linux/macOS builds
do not establish native/runtime compatibility. The prior Android toolchain blocker
remains, and no physical mobile or NES hardware validation has been performed.
Game-specific decoding scripts, ROM inputs and extraction intermediates stay
outside the public application/source package. The only designated music-data
exception is the later four-song demo replacement described above. No general
game music importer is provided.

Revision 5 integration addendum

Format 1004 appends two default-off booleans to regular instruments:
ResetPhaseOnAttack (APU pulse channels) and PitchClampToTimerByte (APU pulse and
triangle channels). The former resets phase once at an attack through the normal
high-timer write, without double-writing when the high byte also changes. The
latter saturates pitch-envelope modulation within the timer low byte; tuning,
fine pitch and slides remain in the unmodulated base. Existing formats through
1003 load both flags as false. Shared UI, all seven locales, text, binary, CRC,
clipboard and undo use the same properties. Duty-cycle text round trips now
preserve explicit all-zero and disabled envelope structures without changing
their historical persistent-effect semantics.

Standalone engines expose FAMISTUDIO_USE_APU_INSTRUMENT_FLAGS (default zero).
Instruction $62 writes the per-channel flags, using three state bytes. The
bundled NSF/NES/FDS kernels enable it. EPSM plus custom tuning shares table lookup
code when the flag feature is enabled, leaving the previous 32-song table and
ROM addresses intact. Four-assembler flag-on/off equivalence and CPU playback
tests cover this path. Exported music headers list the needed option. Preserve
the existing distinction between instrument attack resets and explicit note
phase resets when porting the implementation.

The Windows CI job now includes both revision 4 and revision 5 regression suites.
The shared native S5B reset now clears its 16-cycle timing remainder and selected
register. Rebuild the native library on each platform; no ABI change is needed.
Tests/check_s5b_reset.py uses synthetic programs and the public native ABI to
compare repeated PCM for tone, noise and hardware envelopes in PAL/NTSC and
mono/stereo. It is included in all three desktop CI jobs.
Remote CI, native Linux/macOS playback, Android and physical NES testing remain
separate validation steps; a managed build alone does not establish those results.

Revision 6 integration addendum

Format 1005 preserves the low bit of each DPCM key mapping's initial DAC value.
Mapping controls now show the absolute hardware range 0..127, reusing the existing
localized DMC Initial Value label in all seven languages. The source sample editor
retains its previous half-value representation. Old binary/text mappings retain
their exact even hardware values. New text mappings use DmcInitialValueRaw;
legacy DmcInitialValue remains a half-value field. Undo and clipboard serialize
the same mapping state. The existing engine sample table already stores this
full byte, so no engine opcode, extra runtime state or native ABI is introduced.
Normal attacks can use the mapping reset without a duplicate note DAC command;
no-attack and standalone explicit DAC commands must retain their semantics.
